## 4. 프로젝트 피드백

**질문**

> 내가 한 프로젝트에 대해서 너가 피드백을 해줘

**답변 요약**

코드 전체(`net.gd`, `game.gd`, `main.gd`, 테스트, 빌드 설정)를 읽고 피드백했습니다. 실행해 보지는 않았습니다(로컬에 Godot 없음).

잘한 점

- SDK 없이 Phoenix 프로토콜을 직접 구현한 Realtime 클라이언트가 짧고 명확함
- "가장 먼저 들어온 사람 = 방장" 규칙 하나로 방장 선정과 방장 교체를 해결
- 방장이 판정하고 이동은 각자 처리하는 구조라 반응이 빠름
- 봇 AI가 위험 지도 + BFS로 탈출 경로가 있을 때만 풍선을 놓음
- 스냅샷을 압축된 배열로 보내 트래픽이 적음
- README, CLAUDE.md, 개발 기록 문서가 잘 정리됨

개선할 점 (중요도 순)

1. 숨겨진 탭의 방장이 게임 전체를 멈춤 → 탭이 숨겨지면 방장을 넘기거나 경고 표시
2. 치트 방지 없음: 위치를 검증하지 않고(순간이동 가능), `_from`도 보낸 사람이 직접 적는 값이라 방장 사칭 가능 → 최소한 이동 속도 검증 추가
3. 실제 서비스(`ootd-store`)와 Supabase 프로젝트를 같이 써서 Realtime 사용량을 나눠 씀 → 게임용 프로젝트 분리 권장
4. `sim_test.gd`가 결과를 출력만 하고 실패 판정이 없음 → assert와 종료 코드 추가
5. 물풍선 놓기가 방장 응답을 기다려서 지연이 보임 → 로컬에 먼저 표시(예측)
6. `game.gd`가 1000줄에 시뮬레이션, 봇, 입력, 그리기가 섞여 있음 → 봇과 그리기를 분리
7. Vercel 빌드 때마다 약 1GB 템플릿을 다시 받음 → 빌드 캐시 활용 검토
