# 개발 대화 기록

Claude Code와 함께 크레이지 버블(크레이지 아케이드 스타일 게임)을 만들고 배포한 과정을 질문과 답변 순서대로 정리한 문서입니다.

- 배포 주소: https://jjab-crazyarcade.vercel.app
- 저장소: https://github.com/cau024-droid/261020ai2

---

## 1. 게임 제작 요청

**질문**

> godot 와 supabase의 realtime을 이용해서 혼자 사용가능한 크레이지 아케이드 게임 만들어줘.
> 로컬에서만 동작하는게 아니라 링크까지 있어서 다른 사용자도 사용가능하게끔

**답변 요약**

먼저 개발 환경을 확인했습니다.

- 이 PC에는 Godot도 Node.js도 설치되어 있지 않았고, Supabase 프로젝트는 `ootd-store` 하나였습니다.
- Claude 아티팩트 링크는 외부 WebSocket을 막고 파일 하나당 15MB 제한이 있습니다. 그래서 Supabase Realtime을 쓰는 Godot 웹 빌드(40MB 이상)는 그곳에 올릴 수 없고, 별도의 웹 호스팅이 필요하다고 안내했습니다.

진행 전에 정할 것들을 물었고, 다음과 같이 정했습니다.

| 항목 | 결정 |
| --- | --- |
| 빌드와 배포 | Vercel 빌드 서버에서 Godot를 내려받아 웹으로 내보냄 |
| 링크 공유 | 사용자가 직접 공유 |
| Supabase | 기존 `ootd-store` 프로젝트 재사용 (Realtime 채널만 사용, DB 테이블은 건드리지 않음) |
| 게임 모드 | 혼자면 AI 봇과 대전, 친구가 같은 방에 오면 실시간 멀티플레이 |

### 만든 것

| 파일 | 역할 |
| --- | --- |
| `scripts/net.gd` | Supabase Realtime 클라이언트. Godot의 WebSocketPeer로 Phoenix 프로토콜을 직접 구현. Broadcast로 게임 메시지, Presence로 방 인원 관리 |
| `scripts/game.gd` | 15×13 맵, 물풍선과 연쇄 폭발, 아이템 3종, 물방울 갇힘과 터뜨리기, AI 봇, 상태 동기화, 화면 그리기 |
| `scripts/main.gd` | 메뉴와 대기실 UI, 초대 링크(`?room=코드`), 닉네임 저장 |
| `build.sh`, `vercel.json` | Vercel에서 Godot 4.3과 웹 템플릿, 한글 글꼴(Noto Sans KR)을 받아 `build/`로 내보냄 |
| `tests/` | 헤드리스 시뮬레이션 테스트와 화면 캡처 스크립트 |

### 게임 규칙

- 방향키나 WASD로 이동하고 Space로 물풍선을 놓습니다. 모바일은 왼쪽 드래그로 이동하고 오른쪽을 탭합니다.
- 물줄기에 맞으면 3초 동안 물방울에 갇히고, 그사이 상대가 건드리면 터집니다. 마지막까지 남은 사람이 이깁니다.
- 아이템은 풍선 개수, 물줄기 길이, 속도 세 가지입니다.
- 한 방에 최대 4명이 들어오고, 남는 자리는 봇(0~3명)이 채웁니다.

### 네트워크 구조

- 방장(가장 먼저 들어온 사람)이 맵, 폭발, 아이템, 봇, 탈락 판정을 맡고 초당 10번 상태를 보냅니다.
- 각자의 캐릭터 이동은 자기 화면에서 바로 처리하고 위치만 보냅니다. 그래서 조작이 끊기지 않습니다.
- 방장이 나가면 다음 사람이 마지막 상태를 이어받아 계속 진행합니다.

### 검증

- **Realtime:** 브라우저에서 두 클라이언트로 실제 Supabase 프로젝트에 접속해 입장, Presence, Broadcast가 게임 코드와 같은 메시지 형식으로 동작하는 것을 확인했습니다.
- **스크립트와 시뮬레이션:** 사용자 허락을 받아 Godot 4.3 Windows 에디터(약 60MB)만 받아서 스크립트 오류가 없음을 확인했습니다. 헤드리스로 봇 대전 4판을 돌려 모두 승부가 났고(무승부 1판), 다른 클라이언트에 보낸 상태도 방장 맵과 일치했습니다.
- **화면:** 메뉴, 대기실, 게임 화면을 실제로 렌더링해 한글까지 정상인 것을 확인했습니다.

## 2. Godot 설치 방식 질문

**질문**

> 빌드와 배포는 vercel에서 진행하는걸로 해도 괜찮을까?

**답변 요약**

가능하다고 답하고 그렇게 구성했습니다. Vercel 빌드 서버(Linux)가 `build.sh`를 실행해 다음 순서로 진행합니다.

1. Godot 4.3과 웹 템플릿(약 1GB), 한글 글꼴을 받습니다.
2. 스레드를 쓰지 않는 웹 템플릿으로 내보냅니다. 그래서 별도의 보안 헤더(COOP/COEP) 설정 없이도 동작합니다.

로컬 PC에는 코드 검사용 에디터만 받았고, `.tools/` 폴더는 `.gitignore`로 제외했습니다.

## 3. GitHub 업로드와 Vercel 배포 요청

**질문**

> 1. 이 폴더를 GitHub 저장소로 올립니다.
> 2. vercel.com에서 Add New → Project로 그 저장소를 가져옵니다.
>
> 이거 해주고 git에 초기화와 커밋도 해줘 git주소는 https://github.com/cau024-droid/261020ai2 이거야

**답변 요약**

- git 저장소를 초기화하고 커밋 작성자 정보를 이 저장소에만 설정했습니다.
- `.gitattributes`를 추가해서 `build.sh`가 LF 줄바꿈으로 올라가게 했습니다. CRLF로 올라가면 Linux 빌드 서버에서 실행되지 않습니다.
- 첫 커밋을 만들어 `main` 브랜치에 push했습니다.
- Vercel은 로그인이 필요해서, 로그인과 GitHub 권한 승인은 사용자가 직접 했습니다.

## 4. 로그인 완료와 배포

**질문**

> 로그인끝났어
>
> 프로젝트이름은 jjab-crazyarcade로 해서 배포해줘

**답변 요약**

- Vercel에서 `cau024-droid/261020ai2` 저장소를 가져오고, 프로젝트 이름을 `jjab-crazyarcade`로 정해 배포했습니다.
- 빌드 설정은 `vercel.json`이 정합니다(Framework: Other, Build: `bash build.sh`, Output: `build`). 첫 빌드는 1~2분 만에 성공했습니다.
- 배포된 사이트에서 다음을 확인했습니다.
  - 게임이 로드되고 한글 글꼴이 제대로 나옵니다.
  - 링크의 `?room=TEST9`가 방 코드 칸에 자동으로 들어갑니다.
  - 입장하면 Supabase Realtime 방에 접속되고 방장으로 표시됩니다.
  - 게임을 시작하면 봇과 대전이 진행됩니다.
  - 따로 연 Realtime 연결로 들어 보니, 방장이 5초 동안 게임 상태를 35번 보내고 있었습니다.
- 서로 다른 두 기기로 사람끼리 하는 대전은 아직 직접 해 보지 못했습니다.
- 이후 `main`에 push할 때마다 Vercel이 자동으로 다시 배포합니다.
