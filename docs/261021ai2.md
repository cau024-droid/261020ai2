## 4. 프로젝트 피드백

**질문**

> 내가 한 프로젝트에 대해서 너가 피드백을 해줘

**답변 요약**

코드 전체(`net.gd`, `game.gd`, `main.gd`, 테스트, 빌드 설정)를 읽고 피드백했습니다. 실행해 보지는 않았습니다(로컬에 Godot 없음).

잘한 점

- SDK 없이 Phoenix 프로토콜을 직접 구현한 Realtime 클라이언트가 짧고 명확함
- "가장 먼저 들어온 사람 = 방장" 규칙 하나로 방장 선정과 방장 교체를 해결
- 방장이 판정하고 이동은 각자 처리하는 구조라 반응이 빠름
- 봇 AI가 위험 지도 + BFS로 탈출 경로가 있을 때만 풍선을 놓음
- 스냅샷을 압축된 배열로 보내 트래픽이 적음
- README, CLAUDE.md, 개발 기록 문서가 잘 정리됨

개선할 점 (중요도 순)

1. 숨겨진 탭의 방장이 게임 전체를 멈춤 → 탭이 숨겨지면 방장을 넘기거나 경고 표시
2. 치트 방지 없음: 위치를 검증하지 않고(순간이동 가능), `_from`도 보낸 사람이 직접 적는 값이라 방장 사칭 가능 → 최소한 이동 속도 검증 추가
3. 실제 서비스(`ootd-store`)와 Supabase 프로젝트를 같이 써서 Realtime 사용량을 나눠 씀 → 게임용 프로젝트 분리 권장
4. `sim_test.gd`가 결과를 출력만 하고 실패 판정이 없음 → assert와 종료 코드 추가
5. 물풍선 놓기가 방장 응답을 기다려서 지연이 보임 → 로컬에 먼저 표시(예측)
6. `game.gd`가 1000줄에 시뮬레이션, 봇, 입력, 그리기가 섞여 있음 → 봇과 그리기를 분리
7. Vercel 빌드 때마다 약 1GB 템플릿을 다시 받음 → 빌드 캐시 활용 검토

## 8. 4개 관점 서브에이전트 피드백

**질문**

> 내 프로젝트에 대해서 피드백을 해줘. 실사용자 / 디자인 / 시장 / 보안 관점 에이전트가 인터넷 검색과 Claude in Chrome으로 자료를 모아 피드백할 것.

**답변 요약**

- 서브에이전트 4개를 병렬로 돌렸습니다. 실사용자·디자인·시장 에이전트는 Chrome 전용 탭에서 배포 사이트와 참고 사이트를 확인했고, 보안 에이전트는 코드·git 히스토리·응답 헤더만 수동으로 점검했습니다.
- 실사용자: 로딩 빠름(약 11MB, 1초), 진입 마찰 적음. 다만 솔로로 탈락하면 최대 3분간 봇 싸움을 관전해야 하고 나가기 버튼도 없음. 첫 판에 자기 풍선에 쉽게 갇힘. 모바일 레이아웃·터치 버튼 부족. 사운드·연출 없음.
- 디자인: 팔레트 톤 통일은 좋음. 폭탄(#2f7de1)과 파랑 플레이어(#4da3ff)가 겹치고, 물줄기가 민트 바닥에 묻히며, 플레이어 구분을 색에만 의존(색약). 이름표 잘림, 버튼 위계 없음, 타이틀/OG/파비콘 미설정.
- 시장: 넥슨 크레이지 아케이드가 2026-08-13 서비스 종료 → 수요 공백. 4인 방 1개가 초당 약 160건 메시지로 Supabase Free 한도(100/s)를 넘을 수 있음. URL의 `crazyarcade`는 상표 리스크. CrazyGames Basic Launch, 커뮤니티 바이럴 추천.
- 보안: `on_pos`/`on_bomb_request`가 `_from`과 `id`를 비교하지 않아 남의 캐릭터 조작 가능(game.gd:671-690). presence `t` 위조로 호스트 탈취, `_from` 위조로 가짜 스냅샷 가능. 스냅샷 스키마 검증 부족, `ootd-store`와 Realtime 쿼터 공유, build.sh 해시 검증 없음, 보안 헤더 누락.
- 코드는 고치지 않았습니다.
